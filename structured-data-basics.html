構造化データとは（1分で）

構造化データとは、ページの内容を機械が理解できる形でラベル付けしたデータです。人間は文章を読んで「これは会社名」「これは料金」と判断できますが、AIや検索エンジンには明示しないと正確に伝わりません。

たとえば「050-3138-3489」という数字の並びを見て、人は電話番号だと分かります。しかし機械にとっては、それが電話番号なのか、注文番号なのか、確実には判断できません。「これは電話番号です」と機械語で添えるのが構造化データです。

国際的な共通仕様であるSchema.orgという語彙を使い、JSON-LDという形式で書くのが一般的です。ページの見た目は一切変わりません。

まず確認：自社に入っているか

導入を考える前に、現状を確認してください。すでに入っている場合もあります。どちらも無料で、5分で終わります。

方法1：Googleのリッチリザルトテスト（おすすめ）

  • 「リッチリザルトテスト」で検索し、Googleのツールを開く
  • 自社サイトのURLを入力してテストする
  • 検出された種類が一覧で表示される。「アイテムが検出されませんでした」なら入っていません

方法2：ソースを直接見る

  • 自社サイトのページ上で右クリック →「ページのソースを表示」
  • Ctrl + F で application/ld+json を検索する
  • 見つからなければ入っていません

あわせて、robots.txtでAIクローラーを拒否していないかも確認しておくと確実です。読み取りを止めていると、構造化データを入れても意味がありません（よくある失敗の詳細）。

最低限入れる3つ

種類は数百ありますが、中小企業なら3つで十分です。全部を入れる必要はありません。

※商品を販売している場合のみ、Productを追加します。
種類 伝える内容 置く場所
Organization 社名・事業内容・連絡先・公式SNS 全ページ（またはトップ）
FAQPage よくある質問と回答 FAQページ・記事内のFAQ
Article 記事の見出し・公開日・更新日 コラム・お知らせの各記事

店舗や事務所など実店舗がある場合は、Organizationの代わりにLocalBusinessを使います。住所・営業時間・対応エリアまで伝えられるため、「近くの◯◯」で探されるビジネスには必須です。

優先順位は明確で、まずOrganization（またはLocalBusiness）からです。AIが「この会社は実在し、何をしている会社か」を理解する土台になります。

コピペで使えるコード

実際に使える形で載せます。◯◯の部分を自社の情報に置き換えて、HTMLの<head>内に貼るだけです。見た目は変わりません。

① 会社情報（Organization）

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "◯◯株式会社",
  "url": "https://example.com/",
  "description": "◯◯県◯◯市で△△を提供する会社です。",
  "telephone": "000-0000-0000",
  "email": "info@example.com",
  "address": {
    "@type": "PostalAddress",
    "addressCountry": "JP",
    "addressRegion": "◯◯県",
    "addressLocality": "◯◯市",
    "streetAddress": "◯◯1-2-3"
  },
  "sameAs": [
    "https://www.instagram.com/◯◯",
    "https://note.com/◯◯"
  ]
}
</script>

※ sameAs には公式SNSや掲載ページのURLを入れます。「同じ会社である」とAIに伝える重要な項目です。

② 店舗・事務所の場合（LocalBusiness）

上のコードの "@type": "Organization" を "@type": "LocalBusiness" に変え、次の2項目を足します。

  "openingHours": "Mo-Fr 09:00-18:00",
  "areaServed": "◯◯県◯◯市"

③ よくある質問（FAQPage）

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "料金はいくらですか？",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "◯◯円からご提供しています。作業範囲によって変わるため、お見積りでご案内します。"
      }
    }
  ]
}
</script>

※ 質問を増やすときは、{ "@type": "Question" ... } のブロックをカンマ区切りで並べます。

貼り終えたら、必ずリッチリザルトテストで検証してください。書式が1文字崩れているだけで、まるごと無効になります。

業種別の最低セット

自社の業種に合わせて、必要なものだけ入れてください。

※どの業種でもArticleは記事ページに付けます。
業種 最低限のセット 効く理由
飲食・サロン・クリニック LocalBusiness＋FAQPage 「近くの◯◯」で参照される
士業・コンサル Organization＋FAQPage 費用・手続きの質問に答えられる
工務店・リフォーム LocalBusiness＋FAQPage 対応エリアが明確になる
BtoB・製造 Organization＋Article 技術情報が会社と結びつく
EC・小売 Organization＋Product 商品が比較・推奨されやすい

業種ごとの詳しい戦略は業界別AIO戦略にまとめています。

よくある失敗5つ

  • 表示内容と一致していない：ページに書いていない料金や営業時間を構造化データにだけ書く。矛盾はAIの信頼を下げます
  • コピペ元の情報が残っている：他社のサンプルを使い、社名やURLが他社のままという事例は実際にあります。必ず全項目を確認してください
  • 構文が崩れている：カンマ1つの過不足で全体が無効になります。検証ツールで必ず確認を
  • 入れただけで満足する：内容が薄いページに付けても、引用の理由にはなりません
  • 非公開にしたい情報を書く：伏せたい価格などは、構造化データからも除外します

正直な話：これだけでは引用されません

営業上は「構造化データを入れればAIに引用されます」と言いたいところですが、事実は違います。構造化データは、書かれている内容を正確に伝えるための土台であって、内容そのものを良くするものではありません。

「高品質なサービスを提供します」としか書かれていないページに構造化データを付けても、AIが引用する理由は生まれません。逆に、料金・実績・対応範囲が具体的に書かれたページに付ければ、その事実が正確に伝わります。

順番としては、①事実を具体的に書く → ②構造化データで正確に伝えるです。逆にしないでください。書き方はAIが引用したくなる記事作成術で解説しています。

よくある質問

自社サイトに構造化データが入っているか、どうやって確認しますか？

2つの方法があります。1つはGoogleのリッチリザルトテストに自社URLを入力する方法で、検出された種類が一覧で表示されます。もう1つはページ上で右クリックしてソースを表示し、application/ld+json という文字列を検索する方法です。見つからなければ入っていません。どちらも無料で5分あれば確認できます。

構造化データは最低限どれを入れればいいですか？

中小企業なら3つで十分です。会社情報を伝えるOrganization（店舗ならLocalBusiness）、よくある質問を伝えるFAQPage、記事ページに付けるArticleです。この3つでAIが会社を認識する土台ができます。商品を扱う場合はProductを追加します。

構造化データを入れれば、AIに引用されるようになりますか？

それだけでは引用されません。構造化データは情報を正確に伝えるための土台であり、引用されるかどうかは書かれている中身で決まります。事実が具体的に書かれていないページに構造化データを付けても、AIが引用する理由にはなりません。

構造化データは自分で入れられますか？

会社情報とFAQ程度であれば、HTMLを編集できる方なら自分で入れられます。head内にscriptタグを貼るだけで、見た目は一切変わりません。WordPressの場合はプラグインでも設定できます。ページ数が多い場合や、記事ごとに自動生成したい場合は、専門家に依頼したほうが確実です。

構造化データを入れると検索順位は上がりますか？

順位を直接上げるものではありません。ただし内容が正確に伝わることで、検索結果でのリッチな表示やAIの回答での引用につながる可能性があります。順位そのものより、正しく理解されることを目的に考えてください。

まとめ

構造化データは、ページの内容を機械に正しく伝えるためのラベルです。まずリッチリザルトテストで入っているかを確認し、入っていなければOrganization（店舗ならLocalBusiness）・FAQPage・Articleの3つから始めてください。上のコードをそのまま使えます。ただしこれだけで引用されるわけではありません。事実を具体的に書いたうえで使ってこそ効きます。実装まで任せたい場合は、料金プランやよくある質問もご覧ください。
